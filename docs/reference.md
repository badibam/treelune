# Reference — Treelune

The documentation's entry point. This file says what the project is, the rules held in it, and which doc to open for what. The docs listed below are not loaded by default: they are opened when needed.

## What the project is

A native Android application (Kotlin + Jetpack Compose, Room persistence): a personal assistant where the user and the AI have the same capacities to act on the data. Everything goes through the same dispatcher `resource.operation`, whether the action comes from the interface, the AI, the scheduler or the system. `README.md` (English) and `README.fr.md` (French) present the app to whoever discovers it; their generated blocks (tools, AI providers, themes, version) are filled by `scripts/make_readme.py`, from the `tagline` sentence of each tool and each theme. The F-Droid listing, `fastlane/metadata/android/` (`en-US`, `fr-FR`), is written by hand down to its line "The tools:" ("Les outils :"): the list of tools that follows comes from the same script, which also checks F-Droid's length limits.

## Project rules

- Commits in English. An exception assumed to the universal rules: the commits were in French until the switch, the old history stays as it is.
- Comments and debug in English.
- The durable documentation, `docs/` and the READMEs, is in English. The design, `docs/design/` and `TODO.md`, stays in French.
- The strings system is required: `s.tool()`, `s.theme()`, `s.shared()`. No string shown hardcoded in the code. A theme names itself what belongs to it (its name, its palettes) in its own files: the core knows none of them.
- A string lives in two files named by their language: `shared.xml` and a tool's or a theme's `strings.xml` hold the English, which is the resources' default language; `shared-fr.xml` and `strings-fr.xml` hold the French. Android resolves the right language by itself — `StringsManager` goes through `context.resources`, so nothing in the code knows a locale. Both files hold exactly the same keys, and `scripts/check_string_locales.py` checks it at each `./run test`. A file without a translation goes only into the default language, which all the others join by fallback: this is the case of `ai_prompt_chunks.xml`, which goes to the AI and not to the screen.
- Every text the user reads (the app's texts, Guide, demo, README, release notes, F-Droid listing) follows `docs/WRITING.md`: the sentence, and who we talk to, tu in French, README included.
- Never a fallback mechanism without explicit validation. A failure is explicit or is not.
- A date and a duration live in milliseconds everywhere — interface, dispatcher, services, database. ISO 8601 (`2025-03-15T14:30:00+01:00`, `PT1H25M`) and relative periods exist only facing the AI: `AICommandProcessor` and `CommandTransformer` read them on the way in, `CommandExecutor` produces them on the way out. The storage schema marks an instant with `"format": "epoch-millis"` and a duration with `"format": "duration-millis"`; `SchemaModelView` derives from it the schema the AI reads, and `ModelValues` converts an entry's values at the places these marks designate — never according to a key's name or a value's look. The other results (zones, tools, current date) hold an instant only under `timestamp`, `created_at` or `updated_at`, which `DateTimeConverter` knows. The DATE and TIME types stay strings — a day and a time are not instants.
- A single time zone: the one `DateTimeConfig.getZoneId()` returns — the app's setting if there is one, the phone's otherwise. Every date computation or display goes through it: `DateUtils` (including `calendarAt()` for a `Calendar`, and `format()` for a free pattern) and `DateTimeConverter` take it as a parameter. `Calendar.getInstance()`, `SimpleDateFormat`, `ZoneId.systemDefault()` and a `now()` without a zone take the phone's: `scripts/check_timezone.py` refuses them.
- A single calendar, the one the user sets: the hour the day starts, the first day of the week (`TimeResolver`, which the app's code gets through `TimeResolver.at`, never built by hand). What a computation returns decides (`scripts/check_day_bounds.py` guards it): a day (today, in 3 days, the date of an instant) and a period (a day, a week, a month and their bounds) are the app's — at 00:30 with days starting at 4:00, today is the day before; an instant set at a time of the clock (the day before at 18:00, a schedule, what the user writes) is the calendar's. Never a day bound at midnight.
- A key is written in snake_case — service parameter, result key, schema field, setting name, column. camelCase is reserved for Kotlin identifiers. A key most often lives in a string, but not always: a property of a `@Serializable` class also names a JSON field, and therefore bears a `@SerialName` in snake_case — like `@ColumnInfo` for a Room column. Only exception: the vocabulary that is not ours, that of JSON Schema (`additionalProperties`, `minLength`…), that of Vega-Lite in a Chart's config (`strokeDash`, `strokeWidth`), that of MCP which the app's server speaks (`protocolVersion`, `inputSchema`…), that of Tailscale's access policy which the external access screen gives to copy (`nodeAttrs`), that of SVG in a texture pattern's cell (`viewBox`), that of Android's vector icons, read as XML for an icon's strokes (`pathData`, `fillColor`), and that of PNG, a chunk's name read in a file's first bytes to recognise an animated image (`acTL`). `./scripts/check_key_case.py` keeps it: no camelCase key is left, and the check fails as soon as a new one appears.
- A notion that has its brick (`docs/BRICKS.md`: an instant, a thing of the app, a field, a condition…) is entered, stored and read through it — its model, its parser, its selector. A new notion becomes a brick before its first use.
- The database runs on the app's SQLite (`androidx.sqlite:sqlite-bundled`, `BundledSQLiteDriver`), the same on every phone, JSON functions included: a phone under Android 10's did not have `json_extract`. Room no longer opens a `SupportSQLiteDatabase` there: a transaction is written `database.transaction { }` (`AppDatabase`), never `withTransaction`, and a migration is a `ConnectionMigration` (`docs/DATA.md`).
- Check the pattern in the docs before implementing.
- No legacy code left behind: what is replaced is deleted in the same move.
- Comment abundantly, for later reading.
- `./run release` builds the signed release from the working tree, to try it; `./run release-tag [vX.Y.Z]` builds the one that is published, from a clean clone of the tag in `~/.cache/treelune/release/`: its APK is the one F-Droid rebuilds from the tag.
- Compile with `./run compile` — type-check only, which shows only the errors and the verdict.
- Run the tests with `./run test`, which first runs fifteen source checks: the case of keys (`scripts/check_key_case.py`), the agreement between the L1 prompt's examples and the code (`scripts/check_prompt_examples.py`), the parity of keys between languages and each language's quotation marks, « » or “ ”, never straight quotes around a name, the demo's texts included (`scripts/check_string_locales.py`), the time zone (`scripts/check_timezone.py`), the day and week bounds, cut by the user's calendar alone (`scripts/check_day_bounds.py`: nothing at midnight, no weekday written by hand, no `TimeResolver` built by hand outside `TimeResolver`, `Periods` and `DateUtils`), the existence of each text key the code asks for (`scripts/check_string_keys.py`), and the copy of the Cartouche font (Regular, Thin, the italic) and its licence, identical byte for byte to its project's (`scripts/check_font_copy.py`), the spacings, which a screen names through `UI.Space` without ever writing them in dp (`scripts/check_spacing.py`), the READMEs' generated blocks, up to date (`scripts/make_readme.py --check`, which never writes), and the Guide's chapters, in agreement with the code and the demo (`scripts/check_guide.py`: expected operations, places, texts in both languages, the demo's identifiers, the formatting of its texts, icons included, and the label of each setting of the forms a chapter covers), tu in the French texts, README included, from which vous, votre and vos are absent (`scripts/check_french_address.py`), the room left for the floating conversation button by each screen where it floats (`scripts/check_chat_space.py`), Tailscale's correction in the copy of the Go dependencies (`scripts/vendor_go.py --check`), the themes' sounds, in agreement with their choice and their credits (`scripts/theme_sounds.py check`), and the writes of the tables the history covers, made through its one door (`scripts/check_history_writes.py`, `docs/DATA.md`, « History of writes »). Run the suite once, before merging a branch, and leave it green there; not before each commit, a commit of the branch compiling (`./run compile`): several branches run it at the same time, each run then very long. Once means one run, on the tree the merge will give: `develop` unchanged since the branch began, the branch's last commit; moved, `develop` merged into the branch first, then the run; never again after the merge into `develop`, which then brings the tree already tested. A test deserves to exist if it replaces a check on the device: that is the criterion, not a coverage rate.
- When a spec of `docs/design/` is pruned, its guarantees become tests. The code says how; the test says what had been promised, and it is the only form of documentation that cannot lie.
- What the AI providers change without their API saying so (a model withdrawn, a trap, a default) comes from the neighbouring project `provider-facts`: its copy `app/src/main/assets/facts.json`, declared with the facts handled in `provider-facts.json`, is checked by `./run provider-facts`, which `./run release` and `./run release-tag` run first. A withdrawn model cited in the code is corrected; a trap is declared with the note that says how it is handled.
- Generate the strings with `./gradlew generateStringResources`.
- The cosy theme's font, Baloo 2, is copied into `third_party/baloo2/` (variable font, `OFL.txt`, `VERSION`); `scripts/make_baloo_fonts.py` draws from it the five fixed weights `res/font/baloo2_*.ttf`, without the Devanagari, and the embedded licence; its output is committed. Updating Baloo 2 = replace `third_party/baloo2/`, run the script again, commit.
- The external access's Tailscale node is a Go module, `app/src/main/go/`, compiled for arm64 by the NDK (version fixed in `app/build.gradle.kts`) in the Gradle task `buildGoLibrary`, which assembling an APK runs and `./run compile` does not; Go is found through `go.dir` in `local.properties`, or the `PATH`. Its dependencies are copied into `app/src/main/go/vendor/`, committed, with a correction of Tailscale for Android: updating Tailscale = change its version in `go.mod`, run `scripts/vendor_go.py`, read the diff, commit.
- Respect the architecture described in the docs below.

## Complementary docs

- `docs/CORE.md` — system architecture: command dispatcher, service registry, scheduling, discovery pattern, strings, logs.
- `docs/DATA.md` — hierarchical navigation in the data, schema validation, propagation of changes, versioning and migrations.
- `docs/UI.md` — interface components, forms, Compose patterns.
- `docs/themes/` — one doc per theme (its register, its decisions, what stays open), and `sounds.md`, the map of the themes' sound registers.
- `docs/THEMES.md` — the themes: what they are in the app, and the recipe to code one (course, decisions before the code, files, checks, sounds, traps, pass on the phone).
- `docs/WRITING.md` — writing for the user: the rules of the sentence and of address, for every text they read.
- `docs/BRICKS.md` — the bricks (instant, period, thing, field, reduction, condition, filter, entry selection, reading, term): what each chooses, its stored form, its model, its selector, its state; who assembles them.
- `docs/TOOLS.md` — architecture of the tools (tooltypes), extension without touching the core.
- `docs/AI.md` — AI system: state machine, sessions, prompts, automations, providers.
- `docs/EXTERNAL_ACCESS.md` — the external access: the two ways in (an embedded Tailscale node, a relay), the relay's contract, the OAuth, what an outside client sees, the Tailscale node and what Android asks of it.
- `docs/IDENTITY_FILE.md` — the identity file, a public format any producer writes for the app to import (in English, for these producers), and its JSON schema `docs/schemas/identity-file.schema.json`, which `IdentityFileTest` checks.
- `docs/GUIDE.md` — the user's journey: the README, the first launch, the tutorial band and the Guide (`core/guide`, its chapters in `assets/guide/chapters.json`, its texts in `guide.xml` and `guide-fr.xml`, its progress in the settings category `guide`).
- `docs/design/` — transitory design, written to be implemented then pruned. The code and the commits become the register.
- `site/` — the site treelune.app, PHP without framework (`site/public_html/` served, `site/private/` beside it): its words in `texts.php`, English at `/` and French at `/fr/`, its captures and videos declared in `layout.json`, what it reads of the app (tools, themes, the demo's Italian zone) written by `scripts/make_site_data.py`. `./run site` serves it locally, `./run site-shots` takes its captures on a phone holding the demo alone, `./run site-deploy` sends it to OVH; its design is `docs/design/website.md`.
- `docs/theme-tracks.html` — the theme registers mocked up on the same screen of a zone, as previews a click enlarges, opened by `./run tracks`; to read again before proposing or designing a theme (`docs/THEMES.md`, "The course"). Cosy, Swiss, Ink and wash, Metro signage, Cut paper, Architect's blueprint and Monochrome / e-ink (the e-reader) are retained; the others, on hold, each bear a mark by the AI and one by the user out of 10 (`docs/theme-tracks.json`, written by the page): the user's mark ranks them, and that ranking is the order of implementation. On 2026-10-19: Notebook, Terminal, Instruments, JRPG menu, 1-bit Mac, Science-fiction HUD, Risograph, Neon arcade, Playing cards.

## Icons

- The vocabulary is Lucide, whole: an icon's name is a Lucide name. The source is copied into `third_party/lucide/` (SVG, metadata, `LICENSE`, `VERSION`). `scripts/generate_icons.py` draws from it the drawables `lucide_*`, the index `assets/icons/index.json` (tags, categories, former names) and the embedded licence; its output is committed, the build generates nothing. Updating Lucide = replace `third_party/lucide/`, run the script again, commit.
- Every icon on screen is a name of this vocabulary, shown by `UI.Icon` or by the theme — never a glyph or an emoji written in a text. `IconNamesInCodeTest` checks that each name written in the code exists. A text copied to the clipboard is not on screen: no theme draws it, and ✓ or ✗ stay characters there.
- A theme declares `iconSource`: `LUCIDE`, or `OWN` if it draws **all** the icons itself in its `icons/` folder — the script refuses an incomplete theme. `Icons.drawable()` finds a name's image, former name included; a name not found shows as two letters. A pixel theme (the retro) has icons in solid pixels, a box 22 wide: `scripts/pixelize_icons.py` draws them from Lucide (rendered by headless Chrome, coverage threshold), applies the touch-ups by hand of `icon-retouches.txt`, and `generate_icons.py` makes the drawables from them; `--plank` draws in `tmp/` the icons the app names, to judge them by eye.
- A zone and a tool can give their icon a colour (`icon_color`, `IconColor`): a tag name except grey, none by default. The theme draws it (`ThemeContract.ItemIcon`): on a pill in the default theme, in coloured pixels in the retro.
- The app's icon (a tree in front of a crescent moon, on a night blue) is drawn by `scripts/make_launcher_icon.py`, which writes its three layers `res/drawable/ic_launcher_*.xml`: the background, the drawing in colour, and the monochrome Android tints itself; its output is committed. Changing it = modify the shapes or the colours in the script, run it again (it needs shapely), commit. `--store` also draws from it the icon and the banner of the F-Droid listing (`fastlane/metadata/android/en-US/images/`, it needs Pillow too), committed too. It is also the app's mark beside the home screen's title, which each theme draws (`appMark` of `PageHeader`): the two cut layers (`LauncherMark`), or in pixels in the retro, from the grid touched up by hand `themes/retro/app-mark.txt` which the same script converts (`--pixel` gives the computed grid to start again from when the shapes change).
- A zone and a tool can lay a texture on their tile and on the whole background of their page (`texture`, `Texture`, `docs/THEMES.md`): a pattern from a closed list, which each theme draws from its own SVG cells and its tones (`TextureCell`, `TextureTones`, `rememberTextureBrush`), none by default, and which each theme also lays as a full background (`PageGround`); its strength is set for the whole app (Settings › Interface, Textures).
- A notification bears the icon of the tool that sends it (`icon_name` of `notifications.send`), the app's (`NotificationService.APP_ICON`, "sparkles") when no tool sends it — always the Lucide drawing, whatever the theme: the status bar keeps only the silhouette and does not enlarge by a whole factor.
